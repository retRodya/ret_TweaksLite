# ret_TweaksLite — Vision

> Документ отвечает на вопросы «что это, для кого и чего в нём нет».
> Это не спецификация и не список задач: задачи живут в GitHub Issues.
> Меняется редко, и каждое изменение — осознанное решение.

## Одной фразой

Аддон для World of Warcraft Retail и Forever с небольшим набором твиков, которых
автору не хватает в игре: другие аддоны их либо не дают, либо прячут среди сотен
лишних опций.

## Для кого

- Для автора: только те твики, которыми он реально пользуется.
- Для игроков, которым Leatrix Plus и подобные аддоны кажутся избыточными.

## Главный сценарий

1. Игрок открывает окно аддона. Открывается страница General.
2. Выбирает модуль в группе Interface. Справа: «Check the box to enable Tooltips.»
3. Ставит галочку слева от названия модуля. Справа крупно:
   «Type /reload to enable Tooltips.», внизу появляется кнопка Reload UI.
4. Игрок нажимает Reload UI или вводит `/reload`. Модуль запускается.
5. Справа теперь твики модуля чекбоксами. Твик срабатывает сразу, без `/reload`.
6. Рядом со всем, что игрок изменил после последней перезагрузки, видна кнопка
   отката. Одного взгляда на окно хватает, чтобы понять, что накликано.

## Принципы

- **Лёгкий.** Только нужные твики, и у каждого — минимум опций.
- **Модуль — через `/reload`, твик — сразу.** Модуль включается и выключается
  только при загрузке интерфейса: ему не нужно уметь «откатываться» на лету,
  поэтому его код проще и надёжнее. Твики внутри работающего модуля применяются
  сразу, поэтому твиком может быть только то, что легко откатить.
- **Выключенный модуль ничего не стоит.** Не создаёт фреймы, не подписывается
  на события, не ставит хуки и не тратит CPU.
- **Игра возвращается как была.** Игровые настройки (CVar), которые менял модуль,
  восстанавливаются при его выключении — даже если клиент перед этим вылетел.
- **Выглядит как часть игры.** Окно из шаблонов Blizzard, родные шрифты
  и стили подсказок.
- **Один код для двух клиентов.** Одни и те же файлы работают в Retail и Forever.
- **Интерфейс аддона на английском.** Локализация — не раньше, чем аддон стабилен.

## Понятия

| Термин | Значение |
| --- | --- |
| **Module** | Группа твиков на одну тему (Tooltips). В окне — строка в списке слева с чекбоксом и своя страница справа. В коде — отдельный файл. |
| **Tweak** | Одна настройка внутри модуля, чекбокс на его странице. Применяется сразу. |
| **Child tweak** | Твик, который уточняет другой. Стоит под родителем с отступом, виден, пока родитель отмечен, и работает, только пока работает родитель. |
| **General** | Первая строка списка, без чекбокса. Страница приветствия. |
| **Group** | Раздел списка (Interface), только для навигации: включать его не нужно. Сворачивается, на своей странице показывает обзор модулей. |
| **Pending** | Состояние модуля, когда его чекбокс уже изменён, а `/reload` ещё не было. |
| **Undo button** | Кнопка отката справа от названия модуля или твика. Видна, если значение отличается от того, с которым загрузился интерфейс. Клик возвращает это значение. |

## Версия 0.1.0 — что входит

### Окно (ядро)

- Собственное окно аддона из шаблонов Blizzard.
- Слева список: сверху General, ниже группы (Interface), в группах модули.
  General и группы — жёлтым шрифтом, модули — белым.
- У группы слева кнопка «+/−»: показать или скрыть её модули. Состояние запоминается.
- У модуля чекбокс слева от названия, подсказка на чекбоксе — описание модуля.
- Справа рабочая область — страница выбранной строки.
- Страница группы — список её модулей: включённые белым, выключенные серым
  (по галочке, а не по тому, что сейчас работает).
- Страница модуля:

  | Работает сейчас | Чекбокс | Рабочая область |
  | --- | --- | --- |
  | нет | выкл | «Check the box to enable Tooltips.» |
  | нет | вкл | крупно «Type /reload to enable Tooltips.» |
  | да | выкл | крупно «Type /reload to disable Tooltips.» |
  | да | вкл | твики модуля чекбоксами |

- Страница General — приветствие. Содержимое — позже, пока название и описание аддона.
- Кнопка отката справа от названия модуля в списке и справа от названия твика
  на странице модуля. Видна, пока значение отличается от того, с которым
  загрузился интерфейс. Так же будут работать будущие настройки твиков.
- Кнопка Reload UI внизу окна. Видна, пока какой-нибудь модуль ждёт `/reload`.
  Изменённые твики перезагрузки не требуют: они уже работают, а игра сохраняет
  их при `/reload` и выходе.
- Включение и выключение модулей применяется после `/reload`, твиков — сразу.

### Управление

- Окно открывается командами `/rettl` и `/rettweakslite`, из Addon Compartment
  и со страницы аддона в Settings → AddOns.
- Настройки общие для всех персонажей аккаунта.

### Модули

**Interface → Tooltips** — модуль с одним твиком:

- **Health bar above tooltip.** Полоса здоровья на подсказке юнита стоит
  над подсказкой, а не под ней. Это та же полоса Blizzard: твик только
  переносит её и не читает здоровье. По умолчанию выключен.

**Interface → Nameplates** — модуль с одним твиком:

- **Enemy player names in reaction color.** Имена недружественных игроков
  на неймплейтах окрашены в цвет реакции — тот, которым игра красит кружок
  выделения: красный, если игрока можно атаковать, другой цвет, если нельзя.
  Цвет даёт сама игра (`UnitSelectionColor`), аддон его не придумывает.
  Зачем: если полосы здоровья игроков-врагов окрашены в цвет класса, а полосы
  NPC — по типу (кастеры голубые), враг-маг и моб-кастер выглядят одинаково.
  Имя в цвете реакции их различает и заодно показывает, можно ли напасть.
  По умолчанию выключен.

**Interface → Unit Frames** — модуль с одним твиком:

- **Player names in class color.** Имена игроков — и союзников, и врагов —
  на рамках цели, цели цели и фокуса окрашены в цвет класса. Имена NPC,
  в том числе боссов, остаются цвета Blizzard. По умолчанию выключен.
- **Name background on target of target.** У рамки цели есть фон имени в цвете
  реакции, у рамки цели цели его нет. Твик добавляет такой же фон: тот же атлас
  и то же правило цвета, что у Blizzard (`TargetFrameMixin:CheckFaction`),
  для всех юнитов, как у рамки цели. Имя остаётся своего цвета, реакцию
  показывает фон. По умолчанию выключен.

**Developer → Debug** — тестовые версии твиков, которые трудно проверить
в настоящей ситуации:

- **Enemy NPC names in reaction color.** Тот же код, что у Enemy player names
  in reaction color, но для недружественных NPC: враждебные красные, нейтральные
  жёлтые. Проверка без PvP.

## Версия 0.1.0 — что осознанно НЕ входит

- Содержимое страницы General, кроме названия и описания аддона.
- Включение и выключение модулей без `/reload`.
- Профили, импорт и экспорт настроек.
- Локализация.
- Кнопка у миникарты.
- Поиск по модулям.
- Совместимость с аддонами, которые сами двигают или прячут полосу здоровья
  подсказки (TipTac, ElvUI).
- Совместимость с аддонами, которые заменяют неймплейты целиком (Plater,
  ElvUI): твик красит имя только на неймплейтах Blizzard.
- Свой выбор цвета имени: цвет всегда берётся у игры.
- Цвет класса на рамках игрока, группы, боссов, арены и «цели фокуса».
  Понадобится — игроки напишут; группу обычно показывают рейдовыми рамками.
- Цвет реакции для имён на рамках юнитов, в том числе для цели цели
  (см. журнал решений).
- Фон имени на рамке «цель фокуса».
- Публикация на CurseForge — отдельная веха после 0.1.0.

## Когда 0.1.0 готова

- Работает в Retail и в Forever без ошибок Lua.
- Полоса здоровья стоит над подсказкой у игроков, NPC и питомцев, в том числе в бою.
- Имена недружественных игроков на неймплейтах в цвете реакции, в том числе
  в бою; имя меняет цвет сразу, как только меняется PvP-статус игрока;
  имена остальных юнитов не меняются; подсветка имени под мышью в стиле
  неймплейтов Classic сохраняется. До первой проверки в PvP
  код проверен тестом из модуля Debug.
- Имена игроков на рамках цели, цели цели и фокуса в цвете класса, имена NPC
  без изменений; при смене цели цвет меняется сразу.
- У рамки цели цели фон имени в том же цвете, что был бы у рамки цели
  для этого юнита.
- Включение и выключение модуля надёжно применяется после `/reload`,
  твик включается и выключается сразу.
- Рабочая область соответствует состоянию модуля из таблицы выше.
- Выключенный модуль не даёт нагрузки на CPU.
- Проверено в игре по чек-листу.

Для всех юнитов, как фон у рамки цели. | Фон — штатный способ Blizzard показать реакцию на рамке цели, и он не спорит с цветом класса на имени. Не дочерний, потому что полезен и без цвета класса. |

## Знания из references

Находки из чужих аддонов в `references/` и из кода Blizzard. Берём идеи
и знания об API, не код.

### Leatrix Plus

- Хранит два состояния: с каким интерфейс загрузился и что сейчас отмечено
  в чекбоксах. Сравнивает их, чтобы понять, нужен ли `/reload`
  (`LeaPlusLC:ReloadCheck`, `LeaPlusLC:LockOption`).
- Кнопка-шестерёнка крепится справа от текста чекбокса
  (`SetPoint("LEFT", label, "RIGHT")`), текстура `Interface\WorldMap\Gear_64`.
  Серое состояние — `Disable()` и `SetAlpha(0.3)`.
- Выключенная кнопка по умолчанию не показывает подсказку. Нужен
  `SetMotionScriptsWhileDisabled(true)`.
- Своё окно плюс страница в Settings → AddOns
  (`Settings.RegisterCanvasLayoutCategory`), из которой открывается окно.
- Чего не повторять: весь аддон в одном файле на 18 000 строк, а модули,
  требующие `/reload`, перечислены вручную в одной функции. У нас модуль
  сам сообщает ядру о себе.

### Полоса здоровья подсказки

- В Retail это `GameTooltip.StatusBar` (глобальное имя `GameTooltipStatusBar`).
  Она описана в XML (`Blizzard_GameTooltip/Mainline/GameTooltip.xml`): высота 8,
  привязка `TOPLEFT` к `BOTTOMLEFT` подсказки (2, -1) и `TOPRIGHT`
  к `BOTTOMRIGHT` (-2, -1). Код Blizzard на Lua её не перепривязывает,
  а только показывает, прячет и обновляет значение. Значит, достаточно
  перепривязать её один раз при загрузке.
- В Midnight у полосы есть `GameTooltipUnitHealthBarSecureMixin`, а здоровье юнита
  бывает «секретным» значением, которое аддон не может прочитать. TipTac рисует
  свои полосы, но для секретного здоровья оставляет полосу Blizzard. Мы здоровье
  не читаем, поэтому эта проблема нас не касается.
- Проверить в игре: что XML полосы в Forever такой же; что полоса не уходит
  за верхний край экрана, когда подсказка у самого верха.

### Имя на неймплейте

- В 12.x неймплейт — `NamePlateUnitFrameMixin` (`Blizzard_NamePlates`), его
  кадр юнита — `plate.UnitFrame`, имя — `UnitFrame.name`. Цвет имени ставит
  глобальная `CompactUnitFrame_UpdateName` через `name:SetVertexColor`.
  Она же обслуживает рамки рейда и группы, поэтому хук отбирает кадры
  с юнитом `nameplateN`.
- Blizzard красит имена по отношению к игроку только в стиле Legacy
  (`IsUnitNameColored`), в остальных стилях имена белые.
- По документации API (`Blizzard_APIDocumentationGenerated/UnitDocumentation.lua`)
  `UnitIsPlayer`, `UnitIsFriend`, `UnitCanAttack` и `UnitSelectionColor`
  возвращают обычные значения, а `UnitHealth` помечен `SecretReturns = true`.
  Значит, «враг-игрок» и его цвет аддон узнаёт и в бою. `UnitIsUnit` помечен
  `SecretWhenUnitComparisonRestricted` — его лучше избегать.
- Цвет реакции на неймплейте — `UnitSelectionColor(unit, true)`: так Blizzard
  красит имена в стиле Legacy (`colorNameWithExtendedColors = true`) и полосы
  здоровья, когда цвет класса выключен.
- Только в стиле Classic (`ShouldUseClassicCastBar`: `Enum.NamePlateStyle.Classic`)
  имя под мышью Blizzard красит в `YELLOW_FONT_COLOR` через
  `optionTable.nameMouseoverColor`. В остальных стилях подсветки нет.
  Стиль Classic есть только в Retail: в настройках Forever его нет, хотя в коде
  Forever он описан.
- Когда меняется PvP-статус или отношение юнита, приходит `UNIT_FACTION`,
  и `OnUnitFactionChanged` первым делом вызывает `CompactUnitFrame_UpdateName` —
  наш хук сразу перекрашивает имя. В Forever неймплейт слушает это событие
  и для своего юнита, и для `player` (смена твоего статуса), в Retail —
  только для своего юнита.
- Forever (1.60.1, `## Interface: 16001`) — ветка `forever` в Gethe/wow-ui-source.
  Неймплейты там та же система, что в Retail, плюс настройки в папке `Camelot`.

### Имя на рамках цели и фокуса

- `UnitFrame_Update` (`Blizzard_UnitFrame/Mainline/UnitFrame.lua`) ставит текст
  имени, но не цвет: имя остаётся цвета шрифта `GameFontNormalSmall`. Так в Retail
  и в Forever.
- Рамки: `TargetFrame` (юнит `target`), `TargetFrame.totFrame` (`targettarget`),
  `FocusFrame` (`focus`), `FocusFrame.totFrame` (`focustarget`).
- «Цель цели» (`TargetOfTargetMixin`) обновляется из OnUpdate: `UnitFrame_Update`
  для неё вызывается каждый кадр. Хук на эту функцию должен быть дешёвым.
- Фон имени у рамки цели — текстура `ReputationColor` (атлас
  `UI-HUD-UnitFrame-Target-PortraitOn-Type`, слой BACKGROUND).
  `TargetFrameMixin:CheckFaction` красит её `UnitSelectionColor(unit)`, а чужих
  «залоченных» NPC (`UnitIsTapDenied`, не `UnitPlayerControlled`) — серым 0.5.
  У `TargetofTargetFrameTemplate` (120×49, имя 68×10 справа от портрета)
  такой текстуры нет ни в Retail, ни в Forever.
- Ячейка под имя в арте «цели цели» шире, чем рамка текста имени: по ширине
  она совпадает с полосой здоровья (`HealthBar`, 70×10, под именем). Поэтому
  правый край фона привязан к полосе здоровья, а не к имени (видно по скриншоту
  из Forever).
- `UnitClass` помечен `SecretWhenUnitIdentityRestricted`, имя класса —
  `ConditionalSecret`: пока личность юнита скрыта, класс секретный. Проверка —
  `issecretvalue`, которой нет в клиентах без секретных значений.
- Неймплейты дружественных юнитов в подземельях «запрещённые» (forbidden):
  трогать их нельзя, хук пропускает их через `IsForbidden()`.
  `C_NamePlate.GetNamePlates()` без аргументов возвращает только разрешённые.
